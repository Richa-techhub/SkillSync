🔄 3. ER to Relational Mapping Rules Applied

1. Strong Entity Sets

Each strong entity set (USER_ACCOUNT, SKILL) is converted directly into a relational table with simple attributes. Key attributes become Primary Keys.

2. 1:1 Specialization / Roles

STUDENT, COMPANY, and ADMIN are mapped as separate tables containing user_id as a Foreign Key with a UNIQUE constraint, maintaining 1:1 integrity with user accounts.

3. 1:N Relationships

For COMPANY (1) → INTERNSHIP (N), the Primary Key of Company (company_id) is placed as a Foreign Key in the INTERNSHIP table.

4. M:N Relationships

STUDENT ↔ SKILL and INTERNSHIP ↔ SKILL are converted into associative tables (student_skill, internship_skill) using Composite Primary Keys (PK1, PK2) to prevent duplicate associations.

5. Business Rule Triggers

Automated cutoff filtering (e.g. min_cgpa) and application deadlines are enforced via MySQL triggers (trg_auto_discard_ineligible_applicant, trg_validate_application_deadline).

6. Normalization Proof

Every attribute is atomic (1NF), partial dependencies on composite keys are removed (2NF), and all transitive dependencies are eliminated (3NF/BCNF).
